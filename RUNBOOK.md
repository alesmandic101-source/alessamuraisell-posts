# Runbook: publish ONE Instagram post for @alessamuraisell

For scheduled runs. Aleš is not watching: never ask questions, decide and report.

1. **Get the repo.** Attach `alesmandic101-source/alessamuraisell-posts` with push access (add_repo), clone it, then `git pull`.
2. **Read** BRAND.md, PHOTOS.md, QUEUE.md and LOG.md. If LOG.md already has a post dated today (Europe/Ljubljana), stop and report "already posted today".
3. **Pick the post.** Format rule: each ISO week (Mon–Sun) has 2 posts, one Reel and one carousel/single image. If LOG.md has no Reel yet this week, pick a Reel; otherwise pick a non-Reel. A READY **talking Reel** (Aleš filmed it himself) always goes first, whatever the format rule says.
   - First READY item in QUEUE.md of the needed format → use its files and caption as they are. If none of that format is READY: for a Reel, create a new automatic Reel only if QUEUE.md says `Reels approved: yes`; otherwise (or for a carousel) take the first READY item of the other format, or create a new carousel if nothing is READY.
   - No READY item → read INSIGHTS.md first ("Lean the next 1–2 new posts toward", and the topic ideas from comments), then write a new one following BRAND.md. Never copy or repeat an earlier post; default to fresh content. Choose a content type different from the last LOG.md entry, and a topic not used before (check LOG.md and posts/). Copy 3 templates from templates/ into `posts/NN-short-name/slide-1.html` … `slide-3.html` (NN = next number) and change only the text and the photos. **Pick photos by the rotation rule in PHOTOS.md** (least recently used first, big photo and face badge separately). Keep headlines short enough to fit; 2–3 lines max at the template's font size.
   - Creating a new **automatic Reel**: copy the scene-*.html files and reel.json from the newest reel folder in posts/ (or posts/07-reel-stop-guessing), change the text (and photos from assets/ only), keep 4–6 scenes, 9–14 seconds total, keep text between 200px and 1550px from the top. Build with `CHROME=/usr/bin/google-chrome python3 tools/make_reel.py posts/NN-reel-short-name` (same CHROME rule as below), then extract frames with ffmpeg and look at every scene.
4. **Render** (new carousels/singles only): `pip install playwright --break-system-packages`; if `/usr/bin/google-chrome` exists run `CHROME=/usr/bin/google-chrome python3 tools/render.py posts/NN-short-name`, otherwise `python3 -m playwright install chromium` first and run without CHROME. Open every JPEG and look at it: no text cut off or overlapping, his face visible. Fix and re-render if not.
   **Quality check before going further (new posts):** every slide has the red "A" seal, @alessamuraisell, slide count on carousels, his face somewhere in the post, no spelling mistakes, no text cut off or touching another element, no invented numbers or client results, caption 60–150 words in his voice (BRAND.md). If anything fails, fix it; if it can't be fixed, publish the next READY item instead, or nothing.
5. **Push** the post folder to `main` (commit author "Aleš Mandič" <alesmandic101-source@users.noreply.github.com>). Run `git pull --rebase` first. Then wait 60 seconds so GitHub serves the new images.
6. **Publish** with the Windsor.ai for Social Media connector: connector `instagram`, account `17841422405541422`.
   - Carousel: action `create_carousel_post`, `image_urls` = `https://raw.githubusercontent.com/alesmandic101-source/alessamuraisell-posts/main/posts/NN-short-name/slide-1.jpg` (…slide-2, slide-3), in order, plus `caption`.
   - Single image: action `create_image_post` with `image_url` and `caption`.
   - Reel: action `create_video_post` with `video_url` = the raw URL of `reel.mp4`, `cover_url` = the raw URL of `cover.jpg`, `share_to_feed` true, and `caption`. Video processing can take a few minutes; if the action reports it's still processing, wait and check rather than posting again.
   If publishing fails, retry once after 60 s. If it still fails, do not post anything else; report the error.
7. **Record**: add a row to LOG.md (date, folder, type, media id), and update "Last used" in PHOTOS.md for every photo the post used. In QUEUE.md change that item's READY to PUBLISHED <date>. Push.
8. **Keep a buffer (Aleš's rule):** QUEUE.md must always hold at least 4 READY Reels AND at least 4 READY carousels/single images. If either is below 4, create new ones (steps 3–5, do NOT publish them) until both are at 4 or more, add them to QUEUE.md as READY with captions, and push. Every post is prepared and checked days before it goes out.
   **If you can't keep the buffer at 4 + 4 without repeating yourself** (e.g. the same cover photo would appear in 3 of the next 4 items, or you're out of fresh topics in BRAND.md and INSIGHTS.md), tell Aleš exactly what you need, starting with "NEEDS YOU:", for example "NEEDS YOU: send 3–5 new photos of yourself (any recent ones, alone or with adult friends)" or "NEEDS YOU: film one 20-second clip answering: …".
9. **Report** in 2–3 lines: what was posted, the Instagram media id, and anything Aleš needs to do (e.g. "send a pool photo"). If something failed, start the report with "NOT POSTED:" and the reason.

Never: post children, use photos of other people without a consent note in QUEUE.md, invent results/clients/numbers, post more than one item per run, or change BRAND.md.
